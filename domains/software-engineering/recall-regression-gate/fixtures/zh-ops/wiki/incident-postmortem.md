# 故障复盘要求与模板

## 适用范围

P0 与 P1 故障必须在恢复后 **48 小时内**产出复盘文档；P2 由模块自行决定，
但同一类 P2 一个月出现三次以上，必须升级为正式复盘。

## 原则

- **无指责**：复盘针对系统与流程，不针对个人。写「发布流程缺少自动回滚」，
  不写「某某忘了检查」。
- **可验证**：每条改进项必须有责任人、截止日期、验收方式。
- **公开**：复盘文档发布在 wiki，全员可读，不设权限。

## 模板

1. **摘要**：一句话说明发生了什么、影响了谁、持续多久。
2. **时间线**：以分钟为单位，从第一个异常信号到完全恢复，标注每个动作与决策人。
3. **影响面**：受影响客户数、订单数、资损金额、SLA 是否违约。
4. **根因**：直接原因与技术根因分开写。直接原因是「缓存击穿」，
   技术根因可能是「热点 key 没有互斥重建」。
5. **改进项**：分为「立即修复（一周内）」「流程改进（一个月内）」「长期建设（季度）」。
6. **附录**：监控截图、关键日志、相关工单链接。

## 跟踪

改进项录入 Jira 的 `POSTMORTEM` 项目，每周五在稳定性周会上过一遍逾期项。
连续两次逾期未完成的，升级到技术负责人。
