# 发布列车与灰度流程

## 发车时间

- 每周**周二、周四 14:00** 发车，其余时间不接受常规发布。
- **周五不发**，避免问题跨周末无人处理。
- 大促、财报、重大客户上线前一周进入冻结期，冻结期内只允许 hotfix。

## 灰度档位

1% → 10% → 50% → 100%，每档至少观察 **30 分钟**。

观察指标（任一异常即回滚）：

- 5xx 率超过基线 2 倍；
- P99 延迟超过基线 30%；
- 核心接口错误码 Top1 变化；
- 客户端 JS 错误率上升。

## 回滚

- 回滚必须在 **5 分钟内**完成，超过 5 分钟说明发布方式有问题，需单独复盘。
- 回滚优先切流量到旧版本，不依赖重新构建。
- 数据库变更必须向前兼容：先加列不删列，两个月后再清理。

## 抢跑（hotfix）

线上 P0/P1 修复可走 hotfix 通道，需值班经理批准，发布后补记录。
hotfix 不占用发车名额，但每周超过 3 次要在周会上说明原因。
